## Bug 修复：媒体（视频/语音/照片）全部加载失败（401 + CSP 两道拦截）
- 现象：视频加载不出来、语音加载失败、照片不显示，控制台大量报错。用户贴出：`/api/asset` 返回 **401**，以及 CSP 拦截 `cloudflareinsights.com/beacon.min.js`。
- 真正根因（第一道，致命）：`feishu-proxy.js:1303` "所有其他接口需要认证" 中间件对所有路径（含 `/api/asset`）要求 `X-Auth-Token` 用户鉴权；而媒体 URL 按安全设计不带用户 token（只靠 Worker 端租户 token + file_token 能力令牌），于是每条 `/api/asset` 都被 401 拒 → 全部媒体挂掉（含语音，语音本来就是同源代理但不带用户 token 也被 401）。
- 第二道（视频/照片专属）：即使通过 401，`/api/asset` 对照片/视频原本 **302 跳转到飞书 CDN**，最终 URL 落在飞书域名 → 被 CSP `media-src/img-src` 白名单（仅 self + api.tongxi.xyz）拦截。
- 修复（两个 commit，缺一不可）：
  1. `d5063a6`：照片/视频不再 302，改为 Worker **同源流式代理**返回（`new Response(fileResp.body)`，转发 Range 支持拖动）。
  2. `82de185`：在鉴权网关前对 `GET /api/asset` 放行（仍用租户 token + file_token 鉴权，符合"媒体 URL 不带用户 token"设计）；并给 `public/_headers` CSP 的 `script-src`/`connect-src` 加上 `https://static.cloudflareinsights.com` + `https://cloudflareinsights.com`（放行 Pages 自带 Web Analytics 统计脚本，消除刷屏报错）。
- 验证：`curl https://api.tongxi.xyz/api/asset` 现返回 200 `{"error":"file_token is required"}`（不再 401），确认网关已放行；带有效 file_token 即正常返回媒体字节。
- 注意：若个别语音仍"加载失败"，属飞书语音原始格式（AMR/SILK）浏览器无法解码的转码问题，与本次无关，需服务端转码（未做）。
